Changes to the design system

None. Every colour, type step, radius and shadow is a token from the approved system (DEC-039).

Changes to the handoff

  1. No Copy button on the invitation or reset code (a side agent's finding): a Copy button invites pasting link and code into one chat, which defeats the separate code. The code is shown large to be read aloud; the checkbox says "I sent the link and told them the code by phone or in person".
  2. Codes avoid look-alike characters (0/O, 1/I/L) so they can be read aloud.
  3. Recovery-code step on sign-in links back with "Use your authenticator app instead".
  4. The two-factor page's confirmation accepts a recovery code when the old phone is gone.

Notes for the build

  • The invitation and reset token is in the URL fragment (#t=…), so it never reaches a server log or a referrer; the page sends it with the code.
  • Failed sign-ins are counted for unknown usernames too, so "locked" never confirms that an account exists.
  • The QR codes on these boards are samples, not real keys. The real one is an SVG image Goldmark serves, no-store, only to the person enrolling.
  • Disabled actions stay focusable and explain themselves (aria-disabled + Tooltip), so keyboard users learn why.
  • Every action on these screens writes an audit row (DEC-038).
